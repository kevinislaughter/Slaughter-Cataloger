# Slaughter Cataloger 3 — working notes

Rebuild of Slaughter Cataloger (Beta 2.7, now `legacy/beta-2.7/`) agreed 2026-10-08. Workflow stays 1 Library → 2 Issues → 3 Contents → 4 Compiler.

## Architecture (do not drift from this)
- **One schema** (`js/core/schema.js`): every CSV column defined once. Forms, tables, CSV read/write, Speculative/N/A lists and outputs derive from it. Add a field there, nowhere else.
- **One store** (`js/core/store.js`): the only copy of the data. Records are frozen; change = `store.put/remove`, grouped with `store.batch`. Undo/redo and dirty-file tracking live there. Views never keep their own copies.
  Changed files by **revision**: every undo step gives each file it touches a new revision number (never reused); undo/redo restore the file's previous/next number. A file is changed when its revision differs from the one recorded at its last save, or it was marked changed (on load, or restored) and not saved since. Undoing past a save then making a different edit can never look saved (review B-01). A save passes `store.revisions()` taken when it started, so edits made while it writes stay changed. Listeners get `(version, event)`; `event.changed` = `[kind, id]` pairs (used by the journal).
- **Pure logic in core** (`js/core/numbering.js`, `js/core/toc.js`): next-issue numbering and dates, cadence, short names, gaps in a run; contents nesting/reordering and pasted-line parsing. No DOM; unit-tested in Node.
- **One view model for every output** (`js/core/catalog.js`): resolves inheritance and field states once (`issueView`, `titleView`, `contentView`), and writes numbering, dates, physical facts, labels and the typeset entry as "parts" (strings and `{text, spec}`), rendered by `toText`/`toHTML` with speculative values as `[1881?]`. The editors' typeset entry (`IssueEntry`) uses the same `entry()`. `build(store, {titleIDs, issueIDs, nested, limit, date})` → titles (alphabetical, ignoring a leading article; titles without a record last) with issues and contents.
- **Names** (`js/core/names.js`): credits split on `;`, ` & ` and a slash between names (not between digits); match key ignores case, spacing, punctuation and accents; `suggestHeading` (surname first; lower-case particles after the forenames, capitalized ones with the surname; suffixes; roles like "translated by" / ", editor", honorifics and bracketed notes set aside; bodies, single words and initialisms left as given); `index(state)` (forms, heading of each key, entries in word-by-word filing order); `suggestGroups` (same surname, agreeing initials and forenames incl. Wm./Geo./… abbreviations, initialisms like S.E.P. joining the name they spell; ambiguous short forms left out; tie → more shared initials). Pure; `tools/test-names.js`.
- **Outputs** (`js/core/outputs.js`): pure builders on the view model — `checklist` (html/md/txt; styles plain, bibliographic, technical), `catalog` (standalone HTML), `wordpress` (blocks), `proofing` (print HTML), `ris`, `bibtex`; `filename()` = `SCATOUT_<SLUG>[_<TITLEID> when one title]_<TYPE>_<YYYYMMDD>.<ext>`. All user values escaped; 2.7 attribution line kept.
- **Files are the archive** (`js/core/records.js`): read 2.0/3.0 CSVs, migrate, validate, write 3.0. Each record keeps `_src` (its file) and `entryOrder`; saves write back to the same file, keeping that file's BOM/line-ending/quoting style. Unknown columns are preserved. A file's fingerprint (`records.hashText`, used to tell that a file changed on disk or since it was saved) is 128 bits from two seeded cyrb53-style passes plus the length (`c2:` prefix; review 2, R-04); where both texts are at hand, saving compares the texts themselves.
  **Never drop or change a value** (review B-03/B-04/M-02/M-03/M-05): `csv.parse` throws (with the line) on an unclosed quote or text after a closing quote; `readFile` refuses a file with a heading used twice, a column and its alias both present, values under a blank heading, or a row longer than the header. A row with fewer values than the header is refused too (a missing comma shifts values). The file's tool and library slug are the ones most of its rows name. Rows it cannot take in — another tool, another library slug, a repeated TitleID/IssueID/ContentID/AuthorityID, no TitleID — are **set aside verbatim** (`files[name].setAside = [{row, reason, cells}]`) and written back at the end of the file on every save; the Library page lists them. Issues without an IssueID (but with a TitleID) get one minted, like contents. A Parent ContentID that is missing, the item itself, in another issue, listed after the item, or on a loop is not used (item at top level) but kept in `parentKept` and written back; re-nesting in the grid clears it. Parent Item text only links to an earlier item. Yes/No columns read Yes/Y/True/1/X/✓ as yes; a value written any other way is kept in `boolRaw` and written back unless the field changes (unrecognised values are reported). Names in Overridden Fields that are not inheritable fields are kept (`overridesKept`). An issue whose title is not loaded keeps every value and its Overridden Fields exactly as read (`finishIssue` compares with the title only when there is one), so saving it changes neither; the issue form shows such values as its own. Backup files are `…_BACKUP_<digit>…` (a slug may be BACKUP). On a reconnect, files already loaded win over copies that appear (`buildLibrary` `opts.pinned`); the copy is reported as a warning.
- **Session** (`js/app/session.js`): folder open/save (File System Access), browser working copy, reconnect, download fallback. UI never touches files.
  - Files read but not loaded (unreadable, another library, Beta 2, copies) are kept as `store.unloaded` (name → why; persisted with the snapshot, recomputed on every open/load/sync). `store.blocked(name)` refuses a new record whose file would take such a name (the four `fileForNew` call sites say why and add nothing), and `storage.writeFiles` never writes a file new to the app (`mustNotExist`) over one already in the folder (`occupied`) — independent check round 2, item 1. An empty file is not "occupied" and is not counted as unloaded (a first write that failed leaves one; `writeFiles` also removes it where it can) — round 3, A. Names compare without case.
  - Working copy = IndexedDB `kv.session` (snapshot + `seq` + `gen` + mode + folder handle + `diskSeen`) and a `journal` store: every store event appends an entry at once (changed records, all file metadata, dirty list, `gen`); a snapshot replaces the journal after 4 s quiet or 200 entries (one transaction). Every store `load` starts a new `gen` (time-based, unique) that needs its own snapshot; until that is stored the red notice stays (`needsSnapshot`), failed snapshots retry every 5 s. Restore = snapshot + replay of entries of the snapshot's `gen` only (others reported as not restorable, never mixed in); `seq` continues from the highest number in storage. A journal entry that fails sets `needsSnapshot` (the notice stays until a snapshot is stored) and its number goes into `missed`, carried by later entries; restore reports any missing number (named in `missed`, or absent between the snapshot and the last entry replayed) as "could not be restored" (round 2, item 4). Failures are also counted in localStorage (`storage.unstored`, cleared by a stored snapshot), for when nothing later reached IndexedDB to name them (round 3, C) — reported on restore even when no snapshot of the library was ever stored (round 4). Writes are serialized; failures set `ui.storageProblem` (B-06). `flush()` runs a due compaction and resolves when written.
  - One tab at a time (B-07): Web Locks where available (`storage.takeLock`, retried for 2 s because a reload's new page can start before the old one lets go), else a liveness note in localStorage (`slaughter-cataloger-3-owner`, every 2 s, removed on pagehide; fresher than 6 s = taken). Without Web Locks a fresh note from another tab is watched for 2.6 s first: a note that is not renewed was left by a crashed tab, and is taken over. Either way `kv.owner` = this tab's id **fences every IndexedDB write** (checked inside the write's transaction; a stale tab gets `NotOwner` → `access: 'lost'`), and saves check it before writing. Second tab: "Already open in another tab" → `takeOver()`.
  - Saves run one at a time (`save()` queues behind a running save; Ctrl+S included), so an older version of a file never lands on a newer one. The folder handle lives in the same record as the snapshot; a reconnect to a folder holding another library slug reads and writes nothing (`ui.wrongFolder`) until **Choose folder** (`chooseFolder`, keeps unsaved work).
  - Reconnect (`syncFromFolder`) compares the folder with `st.files` and `diskSeen` (every CSV seen at the last read): new files are read, clean changed files re-read, dirty files keep the user's version (a dirty file whose disk text equals what the app would write counts as saved — an interrupted save), files gone from the folder keep their records with `missing: true` (never written again until back, or removed via `forgetFile` with a confirm), files that no longer parse keep their records with `unreadable` (B-02, M-01). Undo history is kept when nothing changed.
  - Save writes each file on its own (`storage.writeFiles` → `{saved, already, backups, conflicts:[{name, backup}], missing, occupied, failed, stopped, notWritten}`); ownership (`stillOwner`) is checked before each file and again just before each write is swapped in (else `abort()`), so a tab taken over mid-save writes nothing more (round 2, item 2). Folder writes run under a second Web Lock (`withSaveLock`): a tab taken over in the instant between its last check and the swap still holds it, so the new tab's save waits, then finds the file changed on disk and backs it up rather than being overwritten after it (round 3; without Web Locks this instant remains). When a tab loses the library, every write it has in progress (backups too) is aborted at once (`storage` `inflight`), so the new tab's save never waits on a doomed write (round 4). An empty file is never backed up; only written files are marked saved; a file already on disk exactly as wanted is not rewritten and not reported as a conflict; a backup is always written before an overwrite (M-04, m-01).
  - Files mode (no folder access): Save downloads; files stay changed until **I've replaced the files** (`confirmDownload`, marks saved at the revisions downloaded) (B-05).
  - `whenReady()` resolves when start-up (restore + folder check) is done; tests wait on it.
- **UI** (`js/ui/*`): Preact + htm, vendored in `js/vendor/` (no CDN, no build step). Views render from (store, route). Route = `#/panel/titleID/issueID`.

## 3.0 data decisions
- **Name authorities**: one file per library, `SCAT_<SLUG>_AUTHORITIES.csv` (tool "Authorities"; kind `authority`; `state.authorities`), AuthorityID `AU-` + 6 chars. Columns are a superset of the Beta 2 `AUTHORITY_<TitleID>.csv` lists (Authorized Form ← AuthorizedForm, Variant Forms ← VariantForms joined with " | ", Type, Roles, Honorifics, Notes, Status "Needs review"/"Confirmed"; plus Dates, See Also, Sources). Count is not stored (derived). A heading matches its listed forms, its own form and that form in direct order. Contents are never changed by headings. `R.mapOfKind` is the one place that maps a kind to its Map.
- **The app reads schema 3.0 only.** Beta 2 (2.0) files are converted once with `tools/convert-to-3.js`; the app lists them as "Beta 2 format, not loaded" and never touches them. `readFile(..., {legacy:true})` is used only by the converter and tests. Versions are normalized ("3" = "3.0", spreadsheets drop the ".0").
- Converter: record-level merge of copies (files sharing IDs; per title for issues). Newest copy of a list is authoritative; records only in older copies go to `_left-out/` verbatim and into the report. Contents merge per issue (newest file holding that issue wins; older-only issues kept). Output: one Titles file per library, one Issues + one Contents file per title, canonical names `SCAT_<SLUG>_TITLES.csv`, `SCAT_<SLUG>_<TITLEID>_ISSUES.csv`, `SCAT_<SLUG>_<TITLEID>_CONTENTS.csv`, plus `CONVERSION-REPORT.md`. Verified by re-reading with the 3.0-only reader.
- Title edits mark issues files changed only when an inherited field, Title Code or First Year changes.
- Changing a TitleID is a deliberate migration done with `tools/change-titleid.js <folder> OLD NEW --out <dir>` (run with `TZ=America/New_York` for the date): IssueIDs/ContentIDs keep their codes with the new prefix, files renamed, a dated sentence is added to General Notes, leftover text mentions are listed. Done once: CHSAHANX-XXXX → CHICAGOX-1985 (Shape-Note Periodicals, 2026-10-08).
- Duplicate or missing Entry Order in a file → row order decides. Speculative/N/A lists also accept internal field keys (e.g. `firstYear`).
- Speculative / N/A lists use canonical CSV header names (2.x label variants mapped via `labelAliases`, unknown names kept).
- Issues inherit 12 title-level fields (`schema.INHERIT`). Issue record holds a value only for overridden fields (`overrides`); CSV writes effective values + `Overridden Fields`. On load: override if listed, N/A, or non-blank and different from the title. **One rule decides inheritance everywhere** (`records.inherits`, used by `effective`, `catalog.issueView` and the issue form): a field is inherited only when the issue does not override it AND holds no value of its own — so an issue read while its title was missing never has its values replaced by the title's when the title is added later (independent check round 3, B). Own values are compared trimmed, as on load. Adding a title in Library also settles such issues in the same undo step (`records.settleIssues`, the load rule: differing values become overrides, equal ones inherited), so the session, the saved files and a reload agree, and a new issue drafted from one carries its overrides (round 4). A ? the issue puts on a value it inherits stays in the view and every output (`catalog.issueView`; round 4 — 49 such marks in the sample data were being dropped).
- Contents get permanent `ContentID` (`TitleID-C` + 6 chars) and `Parent ContentID` (resolved from Parent Item text: same issue, title match, nearest earlier on ties).
- Formula guard (exactly reversible): a value matching `^'*[=+\-@\t\r]` is written with one more leading `'`; reading removes one `'` from a value matching `^'+[=+\-@\t\r]`. `"-- END"` ↔ `'-- END`, `"'-ism"` ↔ `''-ism`. Existing data had one guarded cell (`'-- END`), which reads the same under both rules.
- BibTeX: TeX specials escaped incl. `< > \``, ligatures broken (`-{}-`, `'{}'`), titles/journal double-braced to keep capitals, corporate names or names containing "and" braced as one author, page ranges keep `--`. Checked by Better BibTeX's parser and citation-js (`tools/test-formats.js`).
- Several files with overlapping IDs in a folder → newest loaded, others reported. One Titles file per library. Files from another library slug are skipped.
- Save backs up the disk copy the first time a file is overwritten in a session (and again if it changed on disk). **A backup is never written over** (second review, F2-01): each session gets its own folder `_backups/<date-time>-<8 hex random>` (made only if the name is free, else `-2`…), a name already taken inside it gets `-2`…, each copy is read back and compared before the live file is replaced (else the save of that file fails with the reason), and `BACKUPS.txt` lists every copy (time, copy, original, why). Copies are the file's **bytes** (`arrayBuffer`), checked byte for byte; a copy that fails or doesn't check is removed again (its name was free). The backup folder is tied to the library folder handle and looked for again on every save (deleted → a new one, files copied afresh). `tools/test-backups.js` (Node, in-memory folder holding bytes, frozen clock, forced random clashes).
- **Reading files** (`storage.js` `contentOf`): bytes, decoded as strict UTF-8 with the BOM kept as the first character (csv.js notes it and writes it back, so saves keep it). A file that is not valid UTF-8 (a spreadsheet's plain "CSV" in a Windows code page) is not guessed at: `encodingError` → `records.readFile` refuses it with the reason; its text is the raw bytes one char each, so its fingerprint still changes when it does and it counts as unloaded (never written over).
- Saving refuses while the folder is being read or checked (`ui.busy`); opening, closing, switching or reconnecting a folder waits for a running save (`waitForSave`).
- TitleID is fixed once a title exists (Title Code read-only, First Year value locked; ? still allowed).

## Stage 2 (Issues) — `js/ui/issues.js`
- No issue selected → overview table (with gap rows and the Roman short-name fix offer). Issue selected → run list (left) + issue form. `#/issues/<tid>/new` → a draft.
- A draft follows a base issue: sticky fields and the base's overrides/N/A are carried; numbers and date move on (`numbering.nextIssue`) from the last *regular* issue (not supplement/special) at or before the base; date step = cadence inferred from the last two regular issues unless chosen. Advance choices are remembered per title in localStorage (`sc3.advance.<tid>`, a convenience only). Drafts live in memory per title for the session.
- Short name: follows the previous issue's pattern (`nextShortName`), Roman numerals that touch a letter get separated ("VXIIIN2" → "V.XIII N3"); typing your own stops it following. `fixShortName` powers the one-click, undoable rewrite of old run-together names.
- Record (Ctrl/⌘+Enter) never asks: unaddressed count is shown (click = go to first), duplicates are pointed out. IssueID minted at record time; a new issue after a mid-run base shifts later Entry Orders.
- Gaps: `gapBetween` + `numbersHeld` — numbers missing between consecutive regular issues that the run holds nowhere; each reported once.
- Run list shows short names without the words every short name shares (`sharedStart`), keeping "No."/"Vol.".

## Stage 3 (Contents) — `js/ui/contents.js`
- One grid per issue in Sequence order; nesting = depth from Parent ContentID (`toc.depths`). Sequence kept 1..n on add/move/delete (all real data was already clean 1..n).
- Draft rows (the end row, an inserted row) share the item row's shape and key, so the first value typed turns them into an item without losing the cursor; their ContentID is minted up front.
- Cells and form fields commit only what was typed (a `typed` ref); otherwise they show the record's value. This prevents a stale empty value overwriting a value set from outside (paste, undo).
- Author/Type: spreadsheet-style inline completion (most used, this title's first). Text cells wrap (`field-sizing: content`); Notes fold to one line until focused.
- Paste of several lines / tabbed columns → items (`toc.parseLines`). Top-level items get Parent Item in N/A Fields (as in all converted data).
- Contents whose issue is in no Issues file are listed in the issue picker; their titles appear in the context bar.

## Library › Names — `js/ui/names.js`
- Route `#/names[/<AuthorityID or k:<key>>]`, shown as a tab of Library (rail highlights Library). List (filters All / Headings / No heading / Needs review / Suggested matches, search; first 600 shown) beside a detail pane: a heading (fields, forms with Remove, "Possibly the same name" incl. the bare surname, find a form to add, credits linked to their contents) or a name without one (Make heading with the suggestion editable, Combine with its likely group, Add to a heading). Every change is a store op (undo).

## Run strips — `js/ui/strip.js`
- `RunStrip` in the Issues overview, the Contents issue picker and the title page: rows per volume (numeric order when all numeric) or per year, squares in run order; gaps from `numbering.runGaps` (shared with the Issues run list). Filled = contents, open = none, hatched = missing, ochre = speculative, round = supplement/special.

## Stage 4 (Compiler) — `js/ui/compiler.js`
- No context bar: the stage has its own title list (tick one or several; starts with the route's title). Output, options and selection are remembered in localStorage (`sc3.compiler`, a convenience only). One title → choose some volumes/years (`catalog.scopeGroups`).
- Preview is built from the view model with `limit` 25 issues per title (HTML outputs in a sandboxed iframe, text in a `<pre>`); Download / Copy / Open (blob URL, for printing) build the whole output. The Compiler is the only export besides saving CSVs, and it never writes to the library folder.
- Catalog/WordPress default to top-level items only (2.7's "hide nested" default); proofing, RIS and BibTeX include nested items. Catalog shows an issue's place/publisher/editors/subtitle only where they differ from the title; the Type column only for titles that record types.
- Proofing: explainer → per title a title proof sheet → every issue on its own printed pages (`break-before: page`), every schema field listed (a unit test enforces this), status ?/[N/A]/[blank]/from title; an item and its note are kept together (`tbody.item`).
- RIS/BibTeX: one record per contents item; plain values, speculative fields named in a note; TitleID/IssueID/ContentID carried (BibTeX key = ContentID). Authors are their heading where one exists (option, default on), else the credit without a role; "Credited as:" note when they differ.
- Name index (`names`): web page / Markdown / text; entries = headings, or for unheaded names the suggested heading (or as credited); forms each was credited under; see-references from forms that file under another first word; credits as "Vol. 1, no. 1 (whole no. 1), August 6, 1881, p. 1: “Title” (role)".

## Design
Catalog-card look: cool paper `#EEF1F3`, ink `#1B2430`, ribbon blue `#1F5FA8` for entered values, ochre for speculative, archival red only for unsaved. Spectral (UI, labels, sentence case) + Courier Prime (typed values, IDs). The live typeset entry at the top of each editor is the one signature element. Uncertain values show as `[value?]`.

## Tests — run before every delivery
`sh run-tests.sh` (repository root) runs everything; a skipped required check makes it exit 3 ("not a release check"). The steps, from the repository root:
```
node tools/test-numbering.js                                   # numbering, dates, short names, gaps, contents nesting/paste
node tools/test-store.js                                       # undo/redo, changed-file revisions (B-01)
node tools/test-names.js                                       # credits, headings, matching, suggestions; Authorities round trip
node tools/test-outputs.js sample-data/3.0/egoist-journals     # view model + every output on the whole library
node tools/test-safety.js sample-data/3.0/<library>            # CSV/records never drop or change a value; inheritance (run on each 3.0 library)
node tools/test-backups.js                                     # backups never written over (frozen clock, forced collisions)
node tools/test-roundtrip.js sample-data/beta2/egoist-journals # 2.0 → 3.0 lossless; 3.0 reader refuses 2.0
node tools/convert-to-3.js sample-data/beta2 --out <tmp>       # converter + its own verification
node tools/test-formats.js <dir with node_modules>             # outputs through Better BibTeX's parser, citation-js, Gutenberg's parser
python3 tools/build.py                                         # → dist/slaughter-cataloger-3.html (run-tests checks dist matches)
node tools/test-walkthrough.js dist/slaughter-cataloger-3.html sample-data/3.0/egoist-journals sample-data/beta2/egoist-journals/SCAT_EGOIST-JOURNALS_TITLES.csv [shots-dir]
node tools/test-session.js dist/slaughter-cataloger-3.html sample-data/3.0/folkstudies sample-data/3.0/shape-note-periodicals
```
Playwright is found globally (or set `NODE_PATH=$(npm root -g)`). The walkthrough uses an in-memory folder via `window.__SC_TEST_FS__` (the only test hook in app code); it works out counts from the files and relies on Liberty's last issue (vol. 17, no. 1, whole no. 403, Apr 1908). `test-session.js` also serves the app over http://127.0.0.1 to use the browser's real File System Access API (OPFS). Every regression test was confirmed to fail on the build before its fix. `docs/SMOKE-TEST.md` is the manual release check in a real browser and folder.

## Phases
1. Foundation + Library stage (done in first build): schema, store, CSV migration, folder save, title editor; Issues/Contents read-only.
2. Issues and Contents editing (done, 2026-10-09): issue drafts with auto-advance/sticky/inheritance, gaps, short-name fix; contents grid with paste, bulk add, nesting, reorder, completion.
3. Compiler on one view model (done, 2026-10-09): checklist, catalog, WordPress, proofing, RIS, BibTeX; several titles at once; volume/year scope.
4. Gap strips, name authorities, library-wide name index (done, 2026-10-09). The converter turns Beta 2 AUTHORITY_<TitleID>.csv lists into the Authorities file (tested with AUTHORITY_BLKFLAMX-1989.csv → SATANIC-JOURNALS, 410 headings).
5. Readiness review fixes (2026-10-09): every blocker and major finding of the first readiness review (B-01…B-07, M-01…M-06, m-01, m-02) fixed with a regression test, then four rounds of independent verification (round 1: 8 issues, round 2: 4 + minors, round 3: 3 + minors, round 4: 3 + 1 older output bug), each fixed with a test that fails on the build before it. Second external review: one new finding (F2-01, backups could be written over) fixed with `tools/test-backups.js`; external-CSV apostrophe contract documented and tested; README, smoke test, CI added (3.0 release candidate). An independent check of that candidate then found backups copied decoded text (a BOM dropped; a Windows-1252 file's é turned into U+FFFD, in the copy and on saving) and a deleted `_backups` breaking saves: files are now read and backed up as bytes, non-UTF-8 files refused, the backup folder re-checked; file fingerprints are 128-bit.
